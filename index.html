Localhost Exam Simulator

Practise certification exams on your own machine, in conditions close to the real exam. Any AI writes the exam to a fixed format, you load it with a drop or a paste, and the score comes back broken down by domain. If an AI's output won't load, a cheap agent repairs it and you approve the fix with one click.

58 commits, one concern each 48 unit tests passing 0 dependencies Python 3.9+ stdlib · vanilla JS

Run it

To run the web app, pipe the contents of run.txt into your shell:

cd localhost-exam-simulator && cat run.txt | sh      # then open http://localhost:8000

Stop it with Ctrl+C. Tests: python3 -m unittest discover tests. To check a file without loading it: python3 converter.py file.md.

# prompt-exam-parsable-output.md

This file defines the exact output format for a practice exam that will be loaded into my local exam simulator. Follow my message for the content, topics and difficulty, and follow this file only for the structure.

## Output
- Produce ONE markdown file named:
  questions-and-answers-<maker>-<exam>-<number>.md
- Start with the filename on its own line, then the whole file inside a single code block.
- One header, one `# Domains`, one `# Questions`, one `# Answers` section.

## Structure (in this order)
1. A header between two `---` lines: exam_maker, exam_name, exam_number, title, duration_minutes, domain_count
2. `# Domains`: one line per domain, `- D1: <name>` …
3. `# Questions`: `## Q<n>`, the text, exactly four choices `- A)` … `- D)`
4. `# Answers`: `## Q<n>`, `Answer:`, `Domain:`, `Explanation:`

This file defines the exact output format for a practice exam that will be loaded into my local exam simulator.

Output

  • Produce ONE markdown file named questions-and-answers-<maker>-<exam>-<number>.md
  • One header, one # Domains, one # Questions, one # Answers section.

Structure (in this order)

  • A header between two --- lines
  • # Domains: - D1: <name> …
  1. Read the last sentence first. Know what's being asked before reading the scenario.
  2. Scan the options early. Identify the concepts you need to focus on.
  3. Eliminate wrong answers. Narrow down your choices before deciding.
  4. Spot keywords. BEST, FIRST, NOT, and LEAST can change everything.
  5. True ≠ Correct. Choose what answers the question, not just what's technically true.
  6. Stuck between two? Compare their differences against the scenario's requirements.

The header is the identity

The exam's ID is exam_maker-exam_name-exam_number from its header, ignoring case and hyphens, so AI-Engineer and aiengineer are the same name. The filename is ignored, and pasted text needs none. The same maker and name put exams in the same tableau column. An identical copy just says "Already in your library".

Strict on purpose

The parser reports every problem at once instead of guessing. It does tolerate common AI habits: a filename line and a code fence around a pasted reply, Windows line endings, bold labels, and A. or (A) choice styles. Anything else is rejected and offered to Repairs.

Library: the tableau

Exams that share a maker and name form a column, like a solitaire tableau, with cards cascading by number. Many columns scroll sideways inside the felt. List shows every exam as its own card. Search works the way grep does: plain text, or /regex/.

    Repairs, end to end

    1. A load fails. You see every reason, plus "Send this to Repairs?" with an optional "why". Yes saves it as repairs/003/ (the exam as sent, plus the reasons) and appends a sent line to repairs/log.md.
    2. You start any agent with the copied line. It inspects each waiting item. An easy fix gets written to fixed.md with a queued line. Something not worth fixing gets a queued-delete line. Anything odd gets a question, or a declined line. Right before writing, it re-reads the log, and if a line crossed with yours (about 1 in 1,000), it adds a Conflict: note and carries on.
    3. You decide in Settings. Load runs the same check as a normal load. Delete moves the folder to repairs/trash/. Reject takes an optional reason, keeps the attempt as fixed-rejected-N.md and sends the item back. You can add a note to any inbox item, and the agent treats your notes as instructions.
    4. Nothing is truly deleted by the app, and the agent never touches code, your library or your results. The state is just the log: one append-only line per event, cheap enough for a small model.
