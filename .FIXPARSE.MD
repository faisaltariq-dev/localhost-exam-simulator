# Fixing exams that won't import

Hi, and thanks for helping! Here is the situation in plain words.

## The project
A small exam app that runs on the owner's own computer. Other AIs write the exams as markdown, following the format in `prompt-for-exam.md`. The app reads them with `converter.py`, and it refuses any file it can't read with certainty.

## Your job
The files in `parse-inbox/` (named `inbox-001.md`, `inbox-002.md`, …) were refused. For each one: **find out why, and get it to import without damaging anything.**

Look around freely. These help:
- `python3 converter.py parse-inbox/inbox-001.md` prints exactly why a file is refused, or `OK` when it imports.
- `prompt-for-exam.md` is the format the exam-writing AI was asked to follow.
- `samples/` holds files that import fine, to compare against.
- `python3 -m unittest discover tests` runs the safety checks.

## Two kinds of problems
1. **The parser is too picky.** The file follows the format, or differs from it in a harmless way, but `converter.py` doesn't understand it. Change `converter.py` so it handles this kind of file in general, not just this one file. Then add a small example to `samples/` and a test to `tests/test_converter.py` that fails without your fix.
2. **The file has a small slip.** For example a wrong `exam_number`, a typo in a heading, or `Ans:` instead of `Answer:`. You may fix the file itself.

If a file is really broken, for example a missing question, a missing answer, or a question with only 3 choices, **don't fill the gap yourself.** Leave the file where it is and tell the owner what's missing, so they can ask the exam-writing AI again.

## Please never
- invent, reword or remove questions, choices, answers, domains or explanations
- edit `prompt-for-exam.md` or the plan file (`reproduciable-plan-…md`)
- touch `exams/` or `data/` (the owner's library and results)
- make the tests pass by deleting or weakening a test, or by changing `samples/broken/`. Those files must stay refused.
- delete anything in `parse-inbox/`

## When a file is done
1. `python3 converter.py <the file>` says `OK`, and the tests pass.
2. Move the file to `parse-inbox/ready/`, creating that folder if it doesn't exist.
3. Tell the owner which file it was, what was wrong, and what you changed. They will import it from the library.
4. If you changed code, suggest a short commit message, like `Fix parser: accept "Ans:" labels`, and let the owner decide when to commit. Keep one fix per commit.

## If you're unsure
Stop and ask the owner. Asking is always the right move here.

Thank you!
